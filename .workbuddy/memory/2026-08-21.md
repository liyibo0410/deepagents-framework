# 2026-08-21 工作日志

## 文件上传 404 Bug 修复
- 用户反馈：前端上传文件返回 `Request failed with status code 404`。
- 排查：当前运行中的 FastAPI 进程（PID 50948/61908）只注册了 `POST /api/task`，其他路由（/api/upload、/api/download、/api/files、/ws）全都没注册 → `openapi.json` 路径列表仅 `['/api/task']`。
- 根因：磁盘上的 `api/server.py` 写好了完整路由（5 个 REST + WS），但运行中的进程是历史旧版本（之前修改 server.py 后未重启）。
- 修复：
  1. PowerShell `Stop-Process -Id 50948,61908 -Force` 杀掉旧实例；
  2. nohup 启动 `.venv/Scripts/python.exe main.py` 让其加载磁盘上的新代码；
  3. 重新 curl `/openapi.json` 验证：POST /api/task、POST /api/upload、GET /api/download、GET /api/files 全部 ✅；
  4. `GET /api/upload` 返回 405（而非 404）= 路由已生效；
  5. 用 curl `-F "files=@...;type=text/markdown" -F "thread_id=test_..."` 模拟前端 multipart 上传，返回 `{"status":"uploaded","files":[...]}` HTTP 200，文件成功落到 `upload/session_test_session_*/`。
- 教训：后端代码改动后必须重启服务才能生效，建议后续用 uvicorn `--reload` 模式开发，或在 main.py 启动前做版本标识打印。
